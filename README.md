# Генеалогическое дерево

Публичный просмотр дерева без входа, только для чтения. Сведения и фото редактируются локальным редактором на компьютере владельца; на сайт они попадают отдельной публикацией.

Документация проекта находится в папке `sdlc/` (роли и процессы ИИ-ассистентов — в [ai/](ai/README.md)):

- [sdlc/rules.md](sdlc/rules.md) — договорённости о данных, фото, доступе и Git.
- [sdlc/design-rules.md](sdlc/design-rules.md) — обязательные правила интерфейса и размещения ветвей.
- [sdlc/sdlc.md](sdlc/sdlc.md) — статус реализации, история решений и проверки.
- [sdlc/deploy.md](sdlc/deploy.md) — Firebase, CI, публикация, доступы и откат.
- [AGENTS.md](AGENTS.md) — инструкции для рабочих сессий.

## Данные: папка `Data/`

```
Data/
  Information/
    family-tree.pl.json       основной файл: все родственники, польский текст
    family-tree.ru.json       те же люди и поля, текст на русском
    family-tree.en.json       те же люди и поля, текст на английском
    family-tree.schema.json   схема всех трёх файлов (единственный файл Data/ в Git)
  Photos/                     фотографии; в записях — "photos/<файл>"
  Project/                    family-tree-review.json (вопросы, журнал), family-presentation.json (настройки раскладки)
  Sources/                    присланные оригиналы и подтверждения: <дата>_<ID>/
  Backups/                    резервные копии, которые редактор делает перед каждым сохранением
```

Каждый языковой файл — полная таблица людей и браков, его можно открыть и прочитать отдельно. ID, даты, связи и фото во всех трёх файлах одинаковые, источник фактов — польский файл. RU/EN отличаются только текстовыми полями (имена, места, заметки и т. п.); блок `translation` в конце файла хранит польский текст, с которого сделан каждый перевод. Если польское поле позже изменилось, сайт покажет польский текст с пояснением вместо устаревшего перевода. Утверждённые имена и исходные цитаты автоматически не переводятся.

Редактор сам обновляет все три файла. Если польский файл не правился вручную, текст можно исправить прямо в RU/EN-файле — редактор примет это как перевод; изменённые в копии факты будут отклонены с понятной ошибкой. Всё содержимое `Data/`, кроме схемы, остаётся вне Git.

Сайт получает данные в виде `data/tree.json` и `data/tree.{pl,ru,en}.json` — их создаёт сборка, в проекте этих файлов нет. Для открытия через `file://` сборка готовит `web/family-data.js`; чистый checkout открывает синтетический пример. Интерфейс использует `locales/{pl,ru,en}.json`; после изменения словарей выполнить `python3 scripts/build_locales.py` (обновляет `web/locale-bundle.js`, семейных сведений в нём нет).

## Просмотр и раскладка

- Открыть сведения нажатием на карточку; увеличить фотографию нажатием на портрет. Переходы к родственникам используют подтверждённые связи.
- Материнская ветка слева, отцовская справа; правило повторяется по поколениям. Боковые семьи занимают отдельные области. Подтверждённые действующие супруги образуют пару; неизвестный статус брака не считается действующим.
- Автоматическая сборка и браузер используют один алгоритм `web/family-layout.js`, без исключений для конкретных родственников. Размеры карточек определены в `web/card-metrics.js`.
- Карточки вручную не перемещаются: перетаскивание мышью или пальцем двигает всё дерево.
- На мобильном экране шапка занимает 56 CSS px с добавлением safe area, остальная площадь отдана дереву. Поиск, язык, PDF и легенда находятся в меню. Быстрые действия доступны поверх дерева снизу.
- На сенсорном экране обычный жест перемещает дерево, два пальца меняют масштаб.
- Сведения открываются в нижней панели с разворачиванием. В низком альбомном окне панель сразу занимает экран. Закрытие фото и панели сохраняет контекст просмотра.

`?` означает неизвестную дату. `...` для смерти применяется только при подтверждённом `isLiving: true`. Отсутствие даты смерти не подтверждает, что человек жив.

## Локальный редактор владельца

Нужны Python 3.10+, Node.js и Pillow. Браузерные библиотеки поставляются в `web/vendor`; npm-установка не требуется.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

Дважды нажмите `Uruchom edytor.command` либо запустите:

```sh
.venv/bin/python scripts/editor_server.py
```

Сервер слушает только `127.0.0.1`. Не выставлять его в интернет. Launcher использует `.venv`, подходящее готовое окружение Codex либо `python3`.

«Сохранить» обновляет `Data/Information` (все три языка), журнал в `Data/Project`, офлайн-снимок и при необходимости добавляет фото в `Data/Photos`. Перед записью создаётся резервная копия в `Data/Backups/editor/`. Ошибка подготовки или записи оставляет все файлы прежними. Правка на русском или английском меняет только перевод, факты общие. Оригинальные фото не ретушируются и не удаляются при снятии назначения.

Вне локального редактора (сайт, `file://`) страница только показывает дерево. Несохранённая форма не закрывается по Escape, кнопке закрытия или действию «Показать в дереве» без сохранения/отмены.

После ручного изменения файлов в `Data/` можно обновить только офлайн-снимок:

```sh
.venv/bin/python scripts/build_html.py
```

## Публикация и PDF

Подготовка размещаемого пакета из `Data/`:

```sh
.venv/bin/python scripts/publish_family.py --build-only
```

Папка сайта и её ZIP без публикации: `scripts/build_readonly.py` (результат в `output/hosting/`). Эти команды не создают PDF.

Push в `main` запускает GitHub Actions и production-деплой на Firebase. CI проверяет контрольные суммы и сохраняет уже опубликованные данные, языковые JSON и фото. Отсутствующий или несогласованный снимок останавливает публикацию; синтетический пример вместо семьи не отправляется. Локальные изменения семейных сведений/переводов обычным push не передаются. Явная публикация таких обновлений выполняется отдельно через `scripts/publish_family.py` после окончания Actions. Подробности и откат — в [sdlc/deploy.md](sdlc/deploy.md).

Сайт: <https://family-tree.vynogradskyi.com>. Контрольный адрес Hosting: <https://familytree-9505c.web.app>.

PDF создаётся только по явному действию кнопки «Скачать PDF» из текущего языка и расположения карточек. Формат A0, горизонтально. Автоматически пересоздавать прежний PDF после правок нельзя.

## Проверки

```sh
sh tests/run_all.sh   # всё сразу: Node-тесты, хранилище Data/, сборка, редактор, браузерные тесты, git diff --check
```

По отдельности:

```sh
node tests/check_viewer.cjs            # синтаксис web/*.js, раскладка, языки, цвета, контракты страницы, эталон раскладки
python3 tests/test_family_store.py     # три языковых JSON в Data/Information
python3 tests/test_hosted_build.py
.venv/bin/python tests/test_editor.py
.venv/bin/python tests/test_e2e.py     # браузерные сценарии в Chrome; нужен pip install playwright
git diff --check
```

Регрессионные тест-кейсы и правила их поддержки — [sdlc/test-cases.md](sdlc/test-cases.md). Те же автотесты выполняются в GitHub Actions перед деплоем: при падении публикации нет. Тесты используют синтетические данные. Для проверки интерфейса — мобильные ширины 320, 390, 430 CSS px, низкое альбомное окно и десктоп; фактически проверенные среды фиксировать в `sdlc/sdlc.md`.
