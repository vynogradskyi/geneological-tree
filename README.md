# Генеалогическое дерево

Публичный просмотр дерева без входа. Клиентский семейный прототип открывает редактор карточек и загрузку фото; правки сохраняются только в этом браузере и экспортируются в ZIP. Серверной записи и публичной регистрации нет.

Документация проекта находится в папке `sdlc/` (роли и процессы ИИ-ассистентов — в [ai/](ai/README.md)):

- [sdlc/rules.md](sdlc/rules.md) — договорённости о данных, фото, доступе и Git.
- [sdlc/design-rules.md](sdlc/design-rules.md) — обязательные правила интерфейса и размещения ветвей.
- [sdlc/sdlc.md](sdlc/sdlc.md) — статус реализации, история решений и проверки.
- [sdlc/deploy.md](sdlc/deploy.md) — Firebase, CI, публикация, доступы и откат.
- [AGENTS.md](AGENTS.md) — инструкции для рабочих сессий.

## Данные и языки

Реальные `family-tree.json`, `family-tree-review.json`, `family-translations.json`, фотографии, источники, производные JSON, PDF, ZIP и резервные копии остаются вне Git. Репозиторий содержит код, схему, синтетический пример, публичные словари интерфейса и разрешённые пользователем профили прототипа с хешами паролей. Открытые пароли не сохраняются в исходниках или документации.

HTTP-версия читает `data/tree.json` и `data/tree.pl.json`, `data/tree.ru.json`, `data/tree.en.json`. Связи, ID, даты и пути фото общие; переводятся только текстовые поля. Язык PL/RU/EN сохраняется в браузере. Утверждённые имена и исходные цитаты не переводятся автоматически. Если польское поле изменилось, его устаревший перевод перестаёт применяться и показывается польский текст с пояснением. Сохранение другого поля не делает такой перевод актуальным.

Для открытия через `file://` сохранён подготовленный `web/family-data.js`; чистый checkout открывает синтетический пример. Интерфейс использует `locales/{pl,ru,en}.json`. После изменения словарей выполнить:

```sh
python3 scripts/build_locales.py
```

Команда обновляет публичный офлайн-словарь `web/locale-bundle.js`. Реальные семейные сведения в него не входят.

## Просмотр и раскладка

- Открыть сведения нажатием на карточку; увеличить фотографию нажатием на портрет. Переходы к родственникам используют подтверждённые связи.
- Материнская ветка слева, отцовская справа; правило повторяется по поколениям. Боковые семьи занимают отдельные области. Подтверждённые действующие супруги образуют пару; неизвестный статус брака не считается действующим.
- Автоматическая сборка и браузер используют один алгоритм `web/family-layout.js`, без исключений для конкретных родственников. Размеры карточек определены в `web/card-metrics.js`.
- Перемещение ограничено семейной областью и порядком блоков; подтверждённая действующая пара перемещается вместе. Раскладка — личная настройка браузера, она не меняет родство или основные JSON.
- Undo/Redo и сброс работают с текущей согласованной раскладкой. Если прежняя личная раскладка несовместима с новыми правилами, она сохраняется как отдельная скачиваемая копия. При невозможности сохранить копию исходная запись не перезаписывается.
- На мобильном экране шапка занимает 56 CSS px с добавлением safe area, остальная площадь отдана дереву. Поиск, язык, аккаунт, PDF, легенда и настройки находятся в меню. Быстрые действия доступны поверх дерева снизу.
- На сенсорном экране обычный жест перемещает дерево, два пальца меняют масштаб. Расстановку карточек нужно явно включить в меню; закончить её можно кнопкой над деревом.
- Сведения открываются в нижней панели с разворачиванием. В низком альбомном окне панель сразу занимает экран. Закрытие фото и панели сохраняет контекст просмотра.

`?` означает неизвестную дату. `...` для смерти применяется только при подтверждённом `isLiving: true`. Отсутствие даты смерти не подтверждает, что человек жив.

## Семейный прототип

Размещённый пакет показывает кнопку «Я из семьи» в текущем языке интерфейса. После входа доступны приветствие, выход, редактирование карточек, оригинальные фото и ZIP-экспорт. Гость читает исходный опубликованный снимок; черновики другого аккаунта ему не подмешиваются. Выход не удаляет сохранённые правки.

Это условный клиентский вход, который можно обойти; общего защищённого редактирования на сервере он не предоставляет. Аккаунты хранятся в `web/family-users.json` как логины, отображаемые имена, индивидуальные соли и PBKDF2-SHA256-хеши. Добавление аккаунта со скрытым вводом пароля:

```sh
python3 scripts/manage_family_accounts.py --login LOGIN --first-name NAME --last-name SURNAME
```

Черновики отделены по аккаунтам. Сохранение из устаревшей вкладки отклоняется без перезаписи чужой правки. При обновлении опубликованного снимка предыдущий черновик архивируется; он остаётся доступен после нового сохранения и перезагрузки. ZIP содержит канонические записи, переводы, языковые JSON, новые фото и офлайн-снимок. ZIP сам ничего не публикует.

## Локальный редактор владельца

Нужны Python 3.10+, Node.js и Pillow. Браузерные библиотеки поставляются в `web/vendor`; npm-установка не требуется.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

Дважды нажмите `Uruchom edytor.command` либо запустите:

```sh
.venv/bin/python scripts/editor_server.py
```

Сервер слушает только `127.0.0.1`. Не выставлять его в интернет. Launcher использует `.venv`, подходящее готовое окружение Codex либо `python3`.

В локальном режиме «Сохранить» обновляет JSON, переводы, снимки и фото в папке проекта. Перед записью создаются резервные копии в `backups/editor/`. Ошибка подготовки или записи возвращает прежние исходники и снимки. Оригинальные фото не ретушируются и не удаляются при снятии назначения.

В обычном автономном HTML изменения остаются в IndexedDB. Чтобы перенести их в проект, скачать ZIP и заменить соответствующие файлы; затем проверить данные и подготовить свежий пакет. Несохранённая форма не закрывается по Escape, кнопке закрытия или действию «Показать в дереве» без сохранения/отмены.

После внешнего изменения локальных сведений можно обновить только снимки:

```sh
.venv/bin/python scripts/build_html.py
```

## Публикация и PDF

Подготовка отдельного размещаемого пакета с локальными сведениями и назначенными фото:

```sh
.venv/bin/python scripts/publish_family.py --build-only
```

Для переносимого ZIP также существует `scripts/build_readonly.py`; имя команды историческое, новый пакет включает клиентский семейный прототип. Эти команды не создают PDF.

Push в `main` запускает GitHub Actions и production-деплой на Firebase. CI проверяет контрольные суммы и сохраняет уже опубликованные данные, языковые JSON и фото. Отсутствующий или несогласованный снимок останавливает публикацию; синтетический пример вместо семьи не отправляется. Локальные изменения семейных сведений/переводов обычным push не передаются. Явная публикация таких обновлений выполняется отдельно через `scripts/publish_family.py` после окончания Actions. Подробности и откат — в [sdlc/deploy.md](sdlc/deploy.md).

Сайт: <https://family-tree.vynogradskyi.com>. Контрольный адрес Hosting: <https://familytree-9505c.web.app>.

PDF создаётся только по явному действию кнопки «Скачать PDF» из текущего языка и расположения карточек. Формат A0, горизонтально. Автоматически пересоздавать прежний PDF после правок нельзя.

```sh
node tests/test_card_layout.cjs # также запускает проверки входа, языков, семейных областей и копий раскладки
python3 tests/test_hosted_build.py
.venv/bin/python tests/test_editor.py
git diff --check
```

Тесты используют синтетические данные. Для проверки интерфейса — мобильные ширины 320, 390, 430 CSS px, низкое альбомное окно и десктоп; фактически проверенные среды фиксировать в `sdlc/sdlc.md`.
